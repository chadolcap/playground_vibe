## 확정된 기술 결정

| 항목 | 결정 |
|------|------|
| 언어 / 런타임 | TypeScript, Node.js (v26) |
| 서버 프레임워크 | Colyseus (`@colyseus/schema` 상태 동기화 + 메시지) |
| 클라이언트 3D 엔진 | Three.js + Vite |
| 3D 모델 | 기본 도형을 조합해 코드로 생성 (추후 glTF 교체가 쉽도록 모델 생성부를 분리) |

| 언어 | UI는 한국어, **채팅은 다국어** 지원 예정 (한자·가나·키릴·태국어·아랍어·이모지 등이 빈칸 없이 표시되어야 함) |
| 통신 문서 | xlsx의 기존 다른 프로젝트 시트(lobby, rps, othello, stepping, airhockey, flag, 관리자)를 정리하고 놀이동산용 시트로 새로 구성 |

## 3단계. 서버 — 월드 방(`ParkRoom`)

- [x] `ParkRoom` 생성: 최대 인원 50, 패치 전송 주기 20Hz, 클라이언트당 초당 메시지 40개 제한
- [x] 상태 스키마 정의 (`server/src/schema/ParkState.ts`, 데코레이터 없는 `schema()` API)
  - 통신 필드 이름은 snake_case로 통일 (`room_no`와 동일 규칙)
  - `Player`: session_id, name, color, x/y/z, rot_y, anim(idle/walk/sit), ride_id, seat_index, connected
  - `Ride`: id, seats[] (`Seat`: kind = empty / npc / player, occupant_id = npc_id 또는 session_id)
  - `Npc`: id(`npc_1` 형식, 방마다 1부터), ride_id, seat_index, color
- [x] `park` 방 등록, 입장 시 별명 검증·중복 거부 (2단계에서 먼저 구현 — `server/src/rooms/ParkRoom.ts`)
- [x] 정원(`ROOM_MAX_CLIENTS` = 50)이 차면 `joinOrCreate`가 새 방을 생성 — 방마다 번호(1, 2, …)를 붙이고 비어서 제거된 방 번호는 재사용
  - 입장 직후 `room_info` 요청/응답으로 방 번호·인원을 받아 "N번 놀이동산" 표시 (화면 좌측 상단 배지)
  - 별명 중복 검사는 같은 방 안에서만 적용 (다른 방에는 같은 별명 허용)
- [x] 입장 처리: **오리 색 자동 배정** (모든 사용자가 다른 색 — 황금각 후보 중 사용 중인 색과 가장 먼 hue 선택, 퇴장한 색 자리는 재사용)
  - 스폰: 글로벌페어 입구 주변 반경 4 안에 흩어서 배치
- [x] 이동 메시지 처리: 서버에서 속도·좌표 범위 검증 (순간이동·맵 밖 이동 방지)
  - **이동 예산(토큰 버킷)** 방식: 패킷이 몰려 도착해도 정상 이동은 통과, 거부 시 `move_correction`으로 서버 위치 전송
  - 허용 속도 = `MOVE_RULE.MAX_SPEED`(6) × 1.5, 예산 최대 1초분 / 탑승 중 이동 무시 / `sit`은 클라이언트가 보낼 수 없음
- [x] 탑승 처리: 기구 게이트 거리 검증 → 빈 좌석 배정 → 상태 갱신 / 만석·거리 초과 시 오류 응답
  - 게이트 = 기구 중심에서 맵 중앙 쪽으로 14 떨어진 지점 (`getRideGate`), 4단계 기구 입구도 여기에 맞출 것
  - 요청/응답(`room.request`) 방식, 실패 시 `ServerError(4200, ERROR_CODE)`
- [x] 하차 처리: 좌석 비우고 게이트 주변(반경 2)으로 위치 이동
- [x] NPC 대화 처리: 선택지 ID를 받아 NPC별 대답 반환 (같은 기구 탑승 중 또는 게이트 근처에서만)
  - 선택지 4종은 `shared/npc.ts`, 대답은 `server/data/npc_dialogs.json` (서버 시작 시 누락 검사)
  - NPC 배치: 기구별 `npc_count`만큼 좌석에 고르게 배치 (총 16마리)
- [x] 퇴장 처리: 좌석 반납, 플레이어 제거
  - 비정상 끊김은 20초 재접속 유예 (`connected=false`로 표시, 좌석 유지) → 만료 시 제거·좌석 반납
- [x] 서버 단위 테스트 (`npm test`, `node:test` + tsx): 색 배정, 이동 검증(몰린 패킷 회귀 포함), 게이트·NPC 데이터 — 빌드 시 자동 실행
- [x] 실제 접속 종단 검증: 6명 동시 이동·탑승·만석·하차·NPC 대화·재접속·유예 만료

  - 다른 플레이어 추가·이동·탑승 표시·퇴장 시 제거 / 내 이동이 다른 클라이언트에 그대로 전달 / 순간이동 시 서버 위치로 복귀
- [ ] 재접속 대기 중(`connected=false`) 오리를 따로 표시하는 방법 검토 (현재는 그대로 보임)
- [x] (수정) 놀이기구 움직임 동기화 — 탑승자가 다른 사람에게 엉뚱한 곳에 보이거나 안 보이던 문제
  - 원인: 기구 애니메이션을 클라이언트마다 접속 시점부터 프레임 간격을 더해 진행 → 같은 기구라도 화면마다 열차 위치가 다름
  - 해결: 서버 `time_sync` 요청으로 **방 시각**(방 생성 후 경과 ms)을 맞추고(`game/serverClock.ts`, 왕복 시간이 가장 짧은 표본 사용·10초마다 재동기화), 기구 자세를 방 시각만으로 계산
    - 속도가 변하는 코스터·워터 슬라이드는 한 바퀴를 미리 시뮬레이션한 시간표(`buildLapTimeline`)로 "시각 → 위치" 변환
  - 검증: 두 탭의 방 시각 차이 0ms, 같은 시각 탑승자 위치가 두 화면에서 일치, 같이 탄 두 오리 사이 거리가 양쪽 화면에서 동일(1.84)

## 7단계. 놀이기구 탑승

- [x] 기구 앞 상호작용 영역 판정 → **'타기' 버튼 표시** (`game/rideController.ts`)
  - "기구 근처" = 입구 게이트 반경 안 **또는** 기구 영역(`footprint_radius`) 가장자리에서 3 이내 — `shared/rides.ts`의 `isNearRide()`를 서버·클라이언트가 함께 사용
    - (수정) 처음에는 입구 아치 주변만 인정해서, 기구 바로 옆에 서도 버튼이 나오지 않았음 → 회귀 테스트 추가
  - 클라이언트는 서버 위치 지연을 감안해 0.6 안쪽에서만 버튼 표시, 여러 기구가 겹치면 중심이 가장 가까운 기구
  - 버튼에 서버 상태 기준 빈자리 수 표시, PC 는 `E` 키로도 누름 (`ui/actionBar.ts` — 8단계 '말 걸기'도 같은 버튼 줄 사용)
  - (수정) 버튼 위치: 걸어 다닐 때는 **내 오리 머리 위 말풍선**(이름표 위, 매 프레임 화면 좌표로 투영), 탑승 중 '내리기'는 오른쪽 아래 고정
    - 처음에는 오른쪽 아래에만 있어서 찾기 어려웠음 (사용자 피드백)
- [x] '타기' → 서버 요청 → 배정된 **빈 좌석에 실제로 앉는 모습** 표시 (기구와 함께 움직임), 탑승 중 3인칭 카메라는 최소 14 거리로 물러남
- [x] **우측 상단 탑승 시점 뷰**: 좌석 정면을 바라보는 두 번째 카메라로 같은 씬을 시저(scissor) 영역에 렌더링
  - 그림자 지도는 프레임당 1번만 갱신 (`shadowMap.autoUpdate = false`), 테두리·제목은 HTML 로 겹침
- [x] '내리기' 버튼 → 하차 (게이트 주변에 똑바로 선 자세로 내림, 위치 전송 기준점 초기화)
- [x] 만석일 때 버튼이 '만석'으로 바뀌고 비활성, 그 사이 다른 사람이 먼저 타서 실패하면 안내 문구 표시
- [x] 검증: 걸어서 게이트 접근 → 버튼 표시 → E 키 탑승 → 인셋·내리기 → 하차 후 다시 걷기 / 봇 6마리로 만석 표시 확인
  - 버튼이 활성인 순간 다른 사람이 마지막 자리를 먼저 차지하는 경쟁 상황은 실제로 재현하지 않음 (오류 문구 매핑만 구현)
