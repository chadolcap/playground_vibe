# 놀이동산 3D — 실행 방법

> 작성일: 2026-11-11 (1단계 기반 구성 기준)
> 필요 환경: Node.js v22 이상 (현재 개발 환경 v26), npm

## 1. 의존성 설치 (최초 1회)

서버와 클라이언트는 각각 따로 설치한다.

```bash
cd amusemen_park/server
npm install

cd ../client
npm install
```

## 2. 환경 변수 설정 (선택)

`.env` 파일이 없으면 아래 기본값으로 동작한다.

| 위치 | 변수 | 기본값 | 설명 |
|------|------|--------|------|
| `amusemen_park/server/.env` | `PORT` | `2567` | 서버 포트 |
| `amusemen_park/client/.env` | `VITE_SERVER_URL` | `http://localhost:2567` | 클라이언트가 접속할 서버 주소 |

- `.env` 파일은 git에 커밋하지 않는다.
- 클라이언트의 `.env`를 수정한 뒤에는 클라이언트를 다시 실행해야 반영된다.

## 3. 서버 실행

```bash
cd amusemen_park/server
npm run dev
```

- 아래 메시지가 나오면 정상이다.
  ```
  [server] 포트 2567 에서 대기 중 (방 이름: "park")
  ```
- `server/src`, `shared/` 파일을 수정하면 서버가 자동으로 재시작된다.

## 4. 클라이언트 실행 (새 터미널)

서버를 띄운 터미널은 그대로 두고, 새 터미널을 열어 실행한다.

```bash
cd amusemen_park/client
npm run dev
```

- 파일을 수정하면 브라우저가 자동으로 갱신된다.

## 5. 브라우저 접속

| 기기 | 주소 |
|------|------|
| PC | http://localhost:5173 |
| 같은 와이파이의 모바일 | Vite 실행 화면의 `Network:` 줄에 나오는 주소 (예: `http://192.168.x.x:5173`) |

- 소개·별명 입력 화면에서 별명을 넣고 **입장하기**를 누르면 3D 놀이동산이 나타난다.
  - 좌측 상단에 `🎡 N번 놀이동산`, 하단에 입장 안내가 잠시 표시된다.
- 내 새끼 오리(서버가 배정한 색, 머리 위 별명)가 정문 안쪽에 나타난다.
- 조작
  - PC: `W` `A` `S` `D` 또는 방향키로 이동, 마우스 드래그로 시점 회전, 휠로 확대·축소
  - 모바일: 왼쪽 아래 조이스틱으로 이동, 화면 드래그로 시점 회전, 두 손가락으로 확대·축소
- 놀이기구(또는 입구 아치) 가까이 가면 내 오리 머리 위 말풍선에 `🎢 ○○ 타기 (빈자리 N)` 버튼이 나온다. (PC 는 `E` 키)
  - 타면 좌석에 앉아 기구와 함께 움직이고, 오른쪽 위에 탑승 시점 화면이 나온다. 오른쪽 아래 `🛑 내리기` 로 내린다.
- 기구에 앉아 있는 노란 이름표 오리(`npc_1` 등)는 NPC 다. 기구 근처(또는 같은 기구 탑승 중)에서 `💬 npc_N에게 말 걸기` 를 누르면 대화창이 열리고, 선택지를 고르면 대답한다.
- 같은 방에 들어온 다른 플레이어의 오리(색·별명)가 보이고, 움직임이 실시간으로 반영된다.
  - 브라우저 두 개(또는 PC와 휴대폰)로 각각 입장해 서로 보이는지 확인할 수 있다.
  - 방이 50명으로 가득 차면 다음 사람은 새 방(2번 놀이동산)으로 들어가므로 서로 보이지 않는다.
- 같은 별명으로 다른 탭에서 입장하면 중복 오류 문구가 나와야 한다.

## 6. 모바일에서 서버 접속 시 (2단계 이후)

모바일에서 `localhost`는 모바일 기기 자신을 가리키므로, PC의 IP로 서버 주소를 지정해야 한다.

1. PC의 IP 확인: `ipconfig` → `IPv4 주소`
2. `amusemen_park/client/.env` 작성
   ```
   VITE_SERVER_URL=http://192.168.x.x:2567
   ```
3. 클라이언트 재실행
4. 접속이 안 되면 Windows 방화벽에서 Node.js 접속을 허용한다.

## 7. 빌드 결과물로 실행 (선택)

배포 형태로 확인할 때 사용한다.

```bash
# 서버
cd amusemen_park/server
npm run build    # 타입 검사 후 dist/index.js 생성
npm start

# 클라이언트 (새 터미널)
cd amusemen_park/client
npm run build    # 타입 검사 후 dist/ 생성
npm run preview  # http://localhost:4173
```

## 8. 통신 문서 점검

서버·클라이언트 통신(메시지 type, 오류 코드, 상태 스키마 필드)을 바꾼 뒤에는 통신 문서와 일치하는지 확인한다.

```bash
python amusemen_park/scripts/check_protocol_doc.py
```

- `통신 문서와 코드가 일치합니다.` 가 나오면 정상
- 불일치 항목이 나오면 `doc/놀이동산_온라인.xlsx` 를 갱신한다. (Python `openpyxl` 필요)

## 9. 문제 해결

| 증상 | 원인 / 해결 |
|------|-------------|
| `EADDRINUSE` 오류 | 포트가 이미 사용 중이다. 기존 서버를 종료하거나 `.env`의 `PORT`를 바꾼다 |
| `PORT 환경 변수가 올바르지 않습니다` | `PORT`에는 1~65535 사이의 숫자만 넣는다 |
| `VITE_SERVER_URL 은 http(s) 주소여야 합니다` | `ws://`가 아니라 `http://` 형식으로 적는다 |
| 모바일에서 페이지가 열리지 않음 | PC와 같은 와이파이인지, 방화벽이 허용되어 있는지 확인한다 |
| 입장 시 `서버에 연결할 수 없어요` | 서버가 실행 중인지, `VITE_SERVER_URL` 주소가 맞는지 확인한다 |
